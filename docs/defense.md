# Объяснение для защиты

## Версия 3.1: что показать и объяснить

Nazar Decision: предупреждение содержит цель; 5 минут — временный срок, «до конца» переносится вместе с паузой, прошлое не меняется. Shared settle разбивает интервалы на expiresAt, журнал фиксирует action/domain/time/expiry. Карта показывает интервалы и события, пустым участкам не придумывается причина. /#demo — отдельно помеченный контрольный пример, не личная статистика.

Мобильная PWA — не трекер приложений телефона. В настоящем браузерном тесте самостоятельный таймер восстановился после reload, затем 15-секундный результат с note/taskDone появился в аккаунте. Source=mobile не даёт добавить секунды сайтов и не участвует в KPI бюджета. API дополнительно проверяет ownerId очереди по cookie, включая смену аккаунта в другой вкладке.

Production подготовлен для PostgreSQL/Vercel, локальная SQLite не сброшена. Два Prisma-клиента действительно генерируются, настоящая PostgreSQL 18 проверена локально. Rate limit — общая БД, а не память Functions. Vercel team вернул 403: публичного deployment пока нет, это нужно честно сказать. Qarnaq Academy не менялся. Остальные объяснения ниже остаются базой.

**Пользователь и боль.** Студент учится за ноутбуком, автоматически открывает привычные сайты и замечает потерю времени слишком поздно. Цель, собственные границы и напоминание помогают заметить переключение.

**Как считается время?** Worker — один писатель, popup только команды. Перед сменой контекста закрываем предыдущий полуоткрытый интервал, затем меняем домен/фокус/паузу. Максимум одна HTTP(S)-вкладка Chrome в фокусе. Idle/locked и другое приложение останавливают сайты; пауза останавливает оба счётчика и переносит дедлайн. Нет начисления после дедлайна. После перезапуска/длинного разрыва сохраняем подтверждённое, отмечаем прерывание. 120 секунд без ввода могут исключить чтение; это учёт сайтов, не измерение концентрации.

**Что делает исключение?** YouTube может быть нужен для лекции. Кнопка закрывает прошлый интервал и разрешает домен до конца текущей сессии. Старое отвлекающее время остаётся. Снимок правил не меняется от последующих настроек.

**Почему нет дублей?** UUID сессии остаётся в локальной очереди до подтверждения. UNIQUE(userId,clientSessionId), атомарная запись и хеш payload дают один результат. Повтор с другим содержимым — 409. Статистика из записей, а не увеличиваемого при каждом запросе счётчика.

**Что даёт история?** search находит страницы, getVisits — посещения; считаем локальные visitTime за 7 дней. 100 всего и 3 в окне дают 3. Повтор заменяет снимок. Это не время просмотра. Пользователь выбирает сайты. Разрешение необязательное, сводка на сервер — отдельное согласие и отдельная отправка, URL/заголовки не уходят.

**Где AI?** AI не является частью основного продукта. В разработке использован Codex, что разрешено условиями. Расчёты детерминированы. Возможный AI-комментарий к агрегатам — будущая опция с понятным согласием, не готовая функция.

**Как защищены аккаунты?** Argon2id для паролей, случайные токены и их хеши в базе, HttpOnly/SameSite cookie, Origin/custom header, bearer устройства со сроком и отзывом. Владелец выводится сервером. Очередь ownerId+instanceId не даёт отправить A токеном B. Код подключения случайный, на 5 минут, одноразовый, с ограничением попыток. Публично нужен HTTPS.

Команда должна уметь показать settle/pause/resume/except в shared; serial/persist/sync в worker; auth middleware/проверку instanceId в API; уникальный индекс Prisma; загрузку данных React из API. Нужно знать разницу между автоматическими проверками и реальным Chrome-прогоном по test-report.md. Нельзя заявлять доказанное улучшение успеваемости, уникальность на рынке или отсутствие погрешностей.
