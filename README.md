# Nazar / Назар

**Версия 3.1:** Nazar Decision (5 минут / до конца сессии / вернуться / подробности), журнал решений, интерактивная Attention Map, анализ по правилам, самостоятельный мобильный таймер и PWA, экспорт JSON/CSV и печать отчёта. Production: **https://nazar-orpin.vercel.app** — отдельный проект `qarnaq-academy1/nazar`, постоянная Neon PostgreSQL Free. HTTPS сайт/API, авторизация, MV3 pairing, сохранение/повтор сессии и ZIP проверены 7 ноября 2026. Настройки — [deployment.md](docs/deployment.md).

Учебные сессии с целью, общим бюджетом отвлекающих сайтов и осознанными исключениями. Chrome MV3 + React/TypeScript/Vite + Express + Prisma/SQLite. Основная метрика — **учтённое время на сайтах**, не оценка концентрации или здоровья.

## Быстрый запуск

Node.js **24.x** (проверено 24.21.0), npm, Chrome 120+. Docker, платные сервисы и AI-ключи не нужны. Все команды из корня репозитория:

```powershell
npm ci
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
npm run db:generate
npm run db:migrate
npm run build
npm run dev
```

На Unix вместо Copy-Item: `[ -f .env ] || cp .env.example .env`. Сайт: http://localhost:5173. API: http://localhost:3001/api/health. Используйте именно localhost. Vite проксирует `/api` и `/downloads`. SQLite хранится в `data/nazar.db`. Скрипт миграции сначала создаёт файл базы: это необходимо для движка Prisma в проверенной среде Windows.

```powershell
npm run typecheck
npm test
npm run build
```

Тесты API используют отдельную временную SQLite, настоящие миграции и HTTP-сервер; основная база не затрагивается. Тест worker исполняет его настоящий код с управляемым адаптером Chrome и не заменяет ручную проверку расширения.

## Полный сценарий

1. Зарегистрируйтесь на сайте: email и пароль от 10 символов. Для демо — отдельный тестовый аккаунт и профиль Chrome без личной истории.
2. В «Моих правилах» выберите сайты и бюджет. Для короткого демо: `example.com`, бюджет `0.05` минуты = 3 секунды.
3. Откройте `chrome://extensions`, включите режим разработчика → «Загрузить распакованное расширение» → **`apps/extension/dist`**. Или скачайте ZIP на странице «Расширение», распакуйте, выберите папку с manifest.json. Архив: **`downloads/nazar-extension.zip`**.
4. На сайте создайте код подключения, вставьте в popup Nazar. Код одноразовый, срок 5 минут.
5. Откройте https://example.com. В popup задайте цель и 1–2 минуты, начните сессию. Закройте popup и откройте через несколько секунд: сессия продолжается, бюджет вызывает предупреждение.
6. Нажмите «Этот сайт нужен для задачи». Исключение действует на последующие интервалы только этой сессии. Попробуйте паузу и продолжение.
7. При желании отметьте выполнение задачи, завершите сессию. Итог сначала сохраняется локально, затем отправляется.
8. На сайте нажмите «Обновить» и откройте сессию. Сверьте цель, время сайтов, бюджет, предупреждение и исключение. Новый аккаунт до этого пуст.
9. Для офлайн-проверки остановите API перед завершением. После восстановления нажмите «Синхронизировать». Повтор не создаёт вторую запись.

## Необязательная история

Popup → «Предложения из истории» → пояснение → «Проанализировать последние 7 дней». Отказ в history не ломает таймер. Сайты выбирает пользователь, популярность не назначает их автоматически.

Лимиты: 500 найденных страниц, до 10 000 посещений на страницу, общий порог 50 000 (последняя страница может довести до 60 000). Достижение порогов помечает неполноту. Учитываются `isLocal === true`, `from <= visitTime < to`; общий visitCount не используется. Повторный импорт заменяет снимок. Время просмотра из истории не вычисляется; URL и заголовки не передаются.

Для сводки на сайте отдельно включите согласие в правилах, синхронизируйте и нажмите «Отправить сводку на сайт» в popup. Передаются домен, число посещений, период и полнота. Отключение согласия удаляет серверную сводку. Очистка Nazar не удаляет историю Chrome.

## Конфигурация

| Переменная | Значение и назначение |
| --- | --- |
| PORT | 3001, API |
| WEB_ORIGIN | http://localhost:5173, конкретный origin сайта |
| DATABASE_URL | file:./data/nazar.db; относительный путь от корня |
| NODE_ENV | development; production включает Secure cookie |
| NAZAR_API_URL | http://localhost:3001; публичный API URL при сборке расширения |
| NAZAR_WEB_URL | http://localhost:5173; URL кабинета при сборке расширения |

Для запуска собранного сайта без Vite остановите dev, задайте `NAZAR_WEB_URL=http://localhost:3001`, пересоберите и выполните `npm start`. Сайт и API: http://localhost:3001. В development допускаются WEB_ORIGIN и localhost:3001.

Публичный запуск: HTTPS reverse proxy к loopback API, NODE_ENV=production, WEB_ORIGIN=https://ваш-домен, оба адреса расширения с HTTPS, затем пересборка и обновление расширения в Chrome. Host permission генерируется из API URL. SQLite — на **постоянном диске** с резервными копиями. Внешнее развёртывание не заявляется готовым. В клиенте только публичные адреса; .env и data не публикуются.

## Границы учёта и диагностика

Считается одна HTTP(S)-вкладка сфокусированного обычного окна Chrome. Другое приложение и idle/locked останавливают сайты, но не продлевают сессию. Idle — 120 секунд без ввода; чтение без ввода тоже может исключаться. Только явная пауза останавливает оба счётчика и сдвигает дедлайн. Состояние принадлежит worker, события сериализованы.

Контрольные точки: best-effort 15 секунд, alarm 30 секунд. При новом запуске worker активная сессия прерывается с последним сохранённым итогом. Разрыв свыше 45 секунд или перевод часов назад также прерывает её без начисления разрыва. Даже обычная остановка worker может прервать сессию. Короткий сон/пропущенные события могут давать погрешность в пределах контрольного интервала. Время после дедлайна не учитывается. Это консервативный MVP, а не непрерывный высокоточный трекер.

- API недоступен: проверьте миграции, порт 3001, `/api/health`. Используйте `npm run db:migrate`, включающий создание файла SQLite.
- 403: проверьте WEB_ORIGIN и localhost; production требует HTTPS. Защиту браузера отключать не нужно.
- Если при подключении кодом возникало «Недопустимый источник запроса»: после обновления перезапустите API и нажмите «Обновить» у Nazar в chrome://extensions (не удаляйте расширение). Worker теперь отправляет `credentials: omit`. Только POST /api/pair/exchange принимает корректный Chrome extension Origin с одноразовым кодом, даже если старый клиент прислал cookie сайта. Cookie не используется для обмена и не изменяется. Остальные cookie-действия требуют разрешённый WEB_ORIGIN; действия устройства — проверенный Bearer. CORS остаётся только для конкретных web origins, Chrome worker получает сетевой доступ через host_permissions. Новый код создавайте после перезапуска; переустановка/очистка данных не нужны.
- Код отклонён: создайте новый; срок 5 минут, одно использование, ограничение 30 попыток/15 минут с IP.
- Нет системного уведомления: проверьте настройки ОС; предупреждение остаётся в popup и отчёте.
- Нужен вход: создайте новый код того же аккаунта. Очередь A не отправится токеном B. 401 не удаляет результат.
- 409: другой payload с тем же UUID уже принят. Старый результат не перезаписывается.
- Не меняются адреса: после правки .env выполните сборку и «Обновить» в chrome://extensions.
- npm: нужен интернет к registry и движкам Prisma. C++ Build Tools не нужны; выбран локальный libSQL-драйвер. Предупреждения npm об install scripts изучайте перед разрешением; генерация Prisma явно входит в команды запуска.
